# Architecture

## Principles

1. **Simplest thing that works.** Banners are plain HTML, CSS, vanilla JS with zero dependencies. Heavier tools (React) are used only in the generator app, which is not shipped to ad servers.
2. **Data apart from code.** Copy, colours, fonts, article lists live in JSON/config files.
3. **Modular.** Each tool is an app or package; adding one does not touch the others.
4. **Static first, dynamic later.** Every dynamic feature has a static fallback.
5. **Yarn only.**

## Layout

```
apps/
  generator/        React + Vite + Tailwind v4 + shadcn/ui: banners, header bar, brand manual (one app, static dist/)
packages/
  banner-runtime/   Vanilla TS compiled to one small script (slider)
  templates/        Banner and header-bar HTML/CSS templates, colour logic, validation, types
  brand/            brand.json (colours, logos, fonts, clear space), optimised logo SVGs, helpers
tools/bookmarklet/  Article bookmarklet v2 (source)
tools/              Older standalone tools (migrated gradually)
category/           Older category header (reference for the header bar)
docs/               Documentation
```

Planned, not created yet: `apps/api` (Cloudflare Worker, Phase 2/3). The old plan had `packages/core` and `apps/brand`; types and validation live in `packages/templates`, and the brand manual is a page of the generator.

`format` is `articles-1250x400` or `articles-mobile`; both share one config shape (the mobile template ignores the title and hover colours). `apps/generator/src/lib/banner.ts` picks the template by `format`.

## Banner zip format

```
my-campaign-1250x400.zip
  index.html     CSS and JS inlined, JSON config embedded
  header.webp    Header image (when header type is image)
  ad.jpg         Static ad image (static-ad format only)
```

`index.html` contains a machine-readable block:

```html
<script type="application/json" id="ol-banner">{ ...banner config... }</script>
```

Uploading the zip into the generator reads this block and restores the form exactly. Header bar zips carry the same kind of block with id `ol-header`.

Older Swiper zips have no such block. `apps/generator/src/lib/legacy.ts` reads their slides, links, images, colours and slider options from `index.html`, `style.css` and the inline script, and returns a draft plus notes for the person to check. See [BANNERS.md](BANNERS.md#opening-old-swiper-banners).

## `banner` config

```json
{
  "v": 1,
  "format": "articles-1250x400",
  "campaign": "Kultuurisügis 2710",
  "primary": "#9500b2",
  "header": { "type": "image", "src": "header.webp", "avg": "#8a0aa6", "href": "https://www.ohtuleht.ee/teemalehed/..." },
  "theme": {
    "light": { "bg": "#ffffff", "text": "#272727", "hover": "#e3000f" },
    "dark":  { "bg": "#0f0f0f", "text": "#ffffff", "hover": "#e3000f" }
  },
  "badge": "Sisuturundus",
  "behavior": { "shuffle": true, "autoplay": true, "delayMs": 3000, "speedMs": 250, "loop": true },
  "articles": [
    { "url": "https://www.ohtuleht.ee/1169772/", "title": "...", "image": "https://p.ohtuleht.ee/webp/54/i/2026/10/26/t1ovwidw.aju.jpg", "badge": "Kontsert", "badgeColor": "#0a7a3d" }
  ]
}
```

`header.textInPicture` (optional, picture headers only) means the picture already has the campaign name on it, so the template does not write the name again. Only banners opened from old zips have it; new banners leave it out and the editor shows its checkbox only when it exists.

The main colour `primary` drives the header, the arrows and the default label colour. In each theme, `badge` (label colour) and `headerBg` are optional overrides; when empty, the label colour is the main colour automatically lightened or darkened until it is readable on that theme's background (contrast 4.5:1), and the header is the main colour. Each article may carry its own `badge` text and `badgeColor`; without them the campaign `badge` and theme colour apply. Colours are per campaign. The values above are only the Kultuurisügis preset. Fields are validated by `packages/templates/src/validate.ts`, which returns plain-language problems with the field they belong to.

## ClickTag

The ad server passes `clickMacro` and `clickTag` in the query string. Every template includes the same fixed helper:

```js
var olBanner = {
  getQueryStringValue: function (key) { /* reads query string */ },
  getClickTag: function (url) { /* clickMacro + url, or clickTag */ }
};
```

It is generated by `packages/templates`, never typed by hand, and is not editable in the generator. Every clickable element calls `olBanner.getClickTag(url)`.

## Banner runtime

One small script, no dependencies. Responsibilities:

| Feature | Rule |
|---|---|
| Shuffle | Fisher-Yates on load, before first paint, when `behavior.shuffle` is true |
| Slider | Active only when articles exceed visible count (4 on desktop) |
| Loop | Infinite via cloned edge items and `transform` |
| Input | Arrow buttons, touch swipe, mouse drag, keyboard |
| Motion | Autoplay runs by default; `respectMotion` opt-in obeys `prefers-reduced-motion`; `pauseOnHover` opt-in |
| Theme | CSS variables; dark values under `prefers-color-scheme: dark` |
| Transitions | `slide` (default), `fade`, `cube` for the image slider |
| Budget | Runtime at most about 3 KB gzip |

## Generator app flow

```
Start -> [Upload zip | New banner] -> Form -> Articles -> Preview -> Download zip
```

- Form: campaign, format, header (image or colour, link), badge text and colours, behaviour toggles.
- Articles: paste snippets, paste URLs (Phase 2), manual add, reorder, remove.
- Preview: iframe with desktop/mobile sizes and light/dark switch.
- Weight meter: shows total size against the roughly 100 KB budget (images excluded).

## Article data

Source of article data, in order of preference:

1. Bookmarklet snippet (runs on the article page, no CORS issue).
2. Worker API `/api/article?url=` (Phase 2).
3. Static `feed.json`.
4. Manual entry.

Article images use `https://p.ohtuleht.ee/webp/54/...` (the `/59/` size from `og:image` is swapped to `/54/`).

## Adding a new module

1. Open an issue describing the tool and who uses it.
2. Create `apps/<name>` (UI) or `packages/<name>` (shared code).
3. Keep text and data in a `content.js`/`config.js` or JSON file.
4. Add a README with: run, build, upload, env vars, server settings, open items.
5. Add a row to the module table in the root `README.md` and to `docs/ROADMAP.md`.

## Technology choices

| Need | Choice | Why |
|---|---|---|
| Banner | Plain HTML/CSS/JS | Ad servers need tiny files |
| Generator UI | React + Vite + Tailwind v4 | Much state (forms, lists, preview) |
| Zip | JSZip | Mature, browser-side |
| Icons | Lightweight inline SVG set | No icon font weight |
| Backend | Cloudflare Workers | Site already behind Cloudflare |
| Auth | Microsoft Entra ID | Company accounts |

Check the current version and docs of each library before adding it.
